# Agentic Multi-Model Code Auditor

An experimental AI-powered code auditing system built with Python and LiteLLM Router. It uses specialized LLM-based auditors to review code for potential security vulnerabilities, correctness bugs, and performance issues.

## Overview

The project explores how multiple specialized AI auditors can work together to analyze code and produce a consolidated audit report. A planning component determines which types of checks to run, while LiteLLM Router manages model calls and fallback behavior.

## Key Features

- **Planning:** Selects relevant audit categories based on the submitted code.
- **Specialized auditors:** Separate modules for security, correctness, and performance checks.
- **Multi-model routing:** Uses LiteLLM Router to manage model requests.
- **Fallback handling:** Supports switching to a backup model when the primary model encounters issues such as rate limits.
- **Consolidated reporting:** Combines findings into a readable Markdown report.
- **Basic evaluation:** Tests the system against a small set of predefined code examples.

## Architecture

1. The user submits a code snippet.
2. The planner selects the relevant audit categories.
3. The selected auditors examine the code.
4. The reviewer consolidates their findings.
5. The system returns a structured audit report.

## Setup

1. Clone the repository:

   ```bash
   git clone https://github.com/Asrakhan004/agentic-multi-model-code-auditor.git
   cd agentic-multi-model-code-auditor
   ```

2. Create and activate a virtual environment:

   ```bash
   python -m venv venv
   ```

   Windows PowerShell:

   ```powershell
   .\venv\Scripts\Activate.ps1
   ```

3. Install the project's dependencies.

   Install the required packages used by the project, including LiteLLM and `python-dotenv`, if they are not already listed in a requirements file.

4. Create a `.env` file in the project root and add your own API keys:

   ```env
   GROQ_API_KEY=your_groq_api_key
   GEMINI_API_KEY=your_gemini_api_key
   ```

   Never commit API keys or your `.env` file.

5. Run the project using the entry point or test scripts configured in the repository.

## Evaluation

The current evaluation uses eight predefined test cases covering selected security and correctness scenarios. The initial run completed all eight cases, with four true positives, four true negatives, and no false positives or false negatives under the evaluator's current keyword-based matching logic.

These results are preliminary and should not be interpreted as evidence of production-level reliability. The dataset is small, and the evaluation method has limitations.

## Limitations

- Findings are generated by language models and may be incorrect or incomplete.
- The evaluation dataset is small and covers only selected issue types.
- Keyword-based evaluation does not establish whether a finding is genuinely correct.
- The system is a prototype intended for experimentation and learning, not a replacement for professional security analysis or testing.
